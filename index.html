LLMs & Robotics

A personal course on two connected fields, built from links as they're added. Each module has a summary, deep dives, a self-check and further reading.

LLM how large language models are built, trained, evaluated and served.   Robotics how robots perceive, decide and act.   LLM + Robotics shared foundations, or ideas that carry across both. Robot foundation models (VLAs) are built on LLM backbones, so the two tracks keep meeting.

Sources & summaries → every link added, its summary, the primary sources behind it, saved files and all external references.

18 · our own course

LLM + RoboticsBuild a Robot Brain: 12 weeks, from zero to a robot that understands you (ages 15+)

Our own first-principles course, built from everything in modules 01–17. One lesson a week for 12 weeks, covering robot basics and inference engineering. A learner with basic Python builds Robo-Helper, a simulated robot that understands "put the red block in the bin", plans with A*, stops safely for surprises, and is honestly evaluated (83%). Then they build a tiny neural language model from zero, measure latency, tokens and cost, speed brains up (caching, quantising, distilling, LoRA), plug in Claude as a planner and as a tool-using agent, and race every brain on the same 12 tasks in a simulator with replays. Every lesson has to make the robot measurably better: progress.py shows each one's gain, and the brain the learner builds climbs from 5/12 (word counter) to 8/12 (a tiny LM that writes whole plans) to 10/12 (distilled from a teacher, still 10/12 at 4 bits in 1.4 KB). Extras: attention (how Transformers read), an AI model as judge, and an MCP server so any AI app can drive the robot. Every lesson has a browser playground, real Python homework marked by check.py (100 checks; reference solutions included), hint ladders, and a real-world challenge away from the screen.

#TrackTopicKey takeaway
01LLMLLM evals with decision modelsSet minimum precision and recall first, tune the threshold with CV, verify calibration, then pick on the cost/quality frontier.
02LLM + RoboticsTensorTonic ML practiceDrill the maths and learning half of robotics from scratch: transforms, CV, the RL ladder to PPO, ViT/DDPM. Kinematics, control, estimation and planning need other sources.
03LLM + RoboticsHuman–AI & human–robot helpBlend robot and human control by calibrated confidence, keep intent beliefs revisable, choose ask/act/wait by expected cost, and keep the struggle where the learning is.
04LLM + RoboticsBig teacher, small studentLog a big model on your narrow task, fine-tune the smallest model that meets your bar, evaluate against hand-corrected data split by day, and measure latency on the target device. Milliseconds are metres.
05LLMLLM architecture at scale (Kimi K3)Read architectures along three axes: width (sparse experts, balanced routing), depth (layers that reach back), length (fixed-size memory plus some global attention). Every feature also needs a numerical-stability fix and a serving plan.
06LLM + RoboticsIlya's 30 papersThe toolbox behind robot learning in 30 days: memory (RNN → LSTM → attention), seeing (AlexNet → ResNet), relations and graphs, compression as learning, scale, and learning to act (PPO, RLHF). Start each day with the plain-language box.
07LLM + RoboticsLLM post-trainingPre-training sets what a model knows; post-training sets how it uses it. Three teachers: demonstrations (SFT / behaviour cloning), comparisons (RLHF, DPO), checkers (RLVR / success detectors). Always keep a leash and watch the true metric.
08LLMResearch-engineer roadmapTwelve skills that turn papers into fast, well-tested models. Learn the internals, the data, the architectures, alignment, systems and inference, then reproduce and publish honestly. Most stages tie back to modules 01–07.
09LLMInference engineering, 25 problemsServing is arithmetic plus trade-offs: size the KV cache, keep the GPU busy with continuous batching, protect TTFT with chunked prefill, reuse prefixes, pick precision and GPUs by bandwidth, measure tails, and price it all from explicit assumptions.
10LLM + RoboticsSelf-improving agent harnessesDon't stuff the context: keep it in variables and query it with code and sub-calls (RLM). Let the agent refine its own harness in small, reversible steps without resets (Continual Harness). Read harness benchmarks as "model + harness".
11LLMLLM self-study stackBuild it to understand it: CS336 (pre-training and systems) → Raschka (reasoning, GRPO, distillation) → Lambert (post-training). Plan the hours honestly, and keep your body in the plan.
12LLM + RoboticsTraining & inference videosWatch the mechanisms move: memory and parallelism, LoRA, GRPO, on-policy distillation, optimisers, speculative decoding and serving, each guide tied back to the course's deeper pages.
13LLM100 days of inference engineeringOne chapter of Kiely's book per block, one build per chapter, one written note per day, shared publicly. Start with the smallest model that passes your evals.
14LLM + RoboticsDeep-ML Deep-PathFind your frontier, then drill a few steps a day with spaced review. Read the course page to understand a concept, and do the Deep-Path problems to make it stick. Robotics and control is the thinnest part of the map.
15LLMInference Engineering, interactiveRead the book chapter, run its calculator, then cross-check against the course's own demo and explain any gap. Treat single-setup benchmarks as a starting point.
16LLMHands-On LLM Serving labsBuild a small server yourself (API, scheduler, worker process), then swap in real engines and optimise one change at a time on realistic data. Batching trades latency for throughput, and continuous batching mostly removes that trade.
17LLM + Robotics391 free AI courses, checkedA huge free list is only useful once it's filtered and verified. Keep the classics for foundations, add post-2022 courses for LLMs and robotics, and prefer courses with assignments over lectures alone.
18LLM + RoboticsBuild a Robot Brain (our course)Learn by building: each idea from first principles, then real code, a self-check and a real-world challenge, growing into one working robot that's honestly tested. Then inference engineering: a tiny LM from zero, latency and cost, caching/quantising/distilling, Claude as planner and agent, and a bake-off of every brain.
19LLMEvals field guideAn eval is input, system, grader, number. Read outputs before writing graders, use code for anything definite, and trust an AI judge only after measuring it (kappa, not raw agreement), with the evidence in front of it. Every score gets an error bar; agents get pass^k.
20LLM + RoboticsSix from-scratch reposRead tiny code that does the real thing, run it, then use it to try to make your own robot better, and measure whether it did. Bigger models need more data; a fast brain on a laptop can be too slow on a robot; learned control is great until the world changes.
21LLM + RoboticsRobot maths, played withPlay with each idea first, then use it on your own robot and measure it. Estimation (Bayes, Kalman, Fourier) beats plain averaging once the robot moves; a model of the world only helps if the world has patterns; π0 and GR00T are a scene-understanding Transformer plus a noise-to-motion head.
22LLM + RoboticsGradient, divergence, curlGradient = uphill, divergence = spreading out or draining in, curl = swirl. A robot can drive by following a field, but pure gradients get stuck in dips; a little curl around obstacles gets it round. Measure from many starts, not one.
