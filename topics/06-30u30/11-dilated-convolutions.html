Multi-Scale Context Aggregation by Dilated Convolutions

Space out a 3×3 filter's taps instead of shrinking the image. Each layer can see exponentially further while the output keeps full resolution, which is exactly what pixel-level prediction needs.

AuthorsFisher Yu (Princeton), Vladlen Koltun (Intel Labs)
Year / venue2016 · ICLR
Core ideaDilated convs for dense prediction
Study time2–4 h

Original: arXiv:1511.07122 · Code, notebook and exercises: 30u30 Day 11

Start here (no maths needed)

By spreading out the points a small filter looks at, a network can see a big area of the picture while still giving an answer for every single pixel.

Think of it like this

Imagine checking a big field for weeds through a cardboard tube. You only see a small circle. One way to see more is to stand further back, but then you miss small details. Another way is to look at nine points spread far apart, like a wider net. Do that in several rounds, each time with the points further apart, and soon you have covered the whole field without losing detail.

How it works

  1. A normal filter looks at a small 3-by-3 square of neighbouring pixels.
  2. A dilated filter looks at the same nine points, but with gaps between them.
  3. Layer after layer, the gaps double: 1, 2, 4, 8, 16.
  4. So the area each output pixel "sees" grows very fast, while the number of settings to learn grows slowly.
  5. The picture is never shrunk, so the network can label every pixel: road, person, car, and so on.

Why robots care

To pick up an object, a robot needs to know exactly which pixels belong to it, not just that it is "somewhere in the picture". Labelling every pixel is called segmentation. Good segmentation means the gripper closes on the cup, not on the table next to it.

1. Summary

TL;DR

Classification networks pool and stride until the whole image is one vector. Semantic segmentation needs a label for every pixel, so that lost resolution has to be recovered somehow. This paper avoids losing it. It uses dilated convolutions: the same 3×3 weights, applied to inputs spaced l pixels apart. Stack layers with dilation 1, 2, 4, 8, … and the receptive field grows exponentially while the parameter count grows only linearly, with no pooling at all. The authors build a plug-in context module from these layers. They also show that a VGG-16 with its last two pooling layers removed is simpler and more accurate for segmentation than the earlier adaptations.

  • Dilated convolution is a change to how the operator reads its input, not a bigger filter with zeros in it.
  • Context module: seven 3×3 layers with dilations 1, 1, 2, 4, 8, 16, 1 and a final 1×1. Receptive field 67×67. The basic version has about 64C² parameters.
  • Identity initialisation was essential. With standard random init the module didn't help at all.
  • Simplified front end: 67.6% mean IoU on the Pascal VOC 2012 test set, against 62.2% for FCN-8s and 62.1% for DeepLab, with no CRF.
  • Adding the context module helped in every configuration tested. On the test set it went from 71.3% (front end) to 73.5%, and to 75.3% with a CRF-RNN on top.

2. The core idea

An ordinary discrete convolution and its dilated version, for a 2-D feature map F and a filter k:

(F ∗ k)(p)   = Σ_{s + t = p}     F(s) · k(t)
(F ∗_l k)(p) = Σ_{s + l·t = p}   F(s) · k(t)        # l = dilation factor

stacking 3×3 filters with dilation 2^i:
  F_{i+1} = F_i ∗_{2^i} k_i     →  receptive field of F_{i+1} = (2^{i+2} − 1)²
  • p is an output position, s an input position and t an offset inside the filter (−1, 0 or +1 for a 3×3 filter).
  • With l = 1 this is normal convolution. With l = 2 the taps land 2 pixels apart, so a 3×3 filter spans 5×5 using 9 weights.
  • For a stack of layers with filter size K and stride 1, the receptive field grows by (K − 1)·l per layer: RF = 1 + Σ (K − 1)·l_i.
  • Output resolution never drops, because there is no striding and no pooling.

The paper notes that this operator appears in the wavelet "algorithme à trous", and explains why it prefers the name "dilated convolution": no dilated filter is ever stored.

With the paper's schedule the receptive field after each layer is 3, 5, 9, 17, 33, 65 and 67 pixels wide, matching Table 1. Every pixel inside it is covered. Seven plain 3×3 layers reach only 15 pixels with the same 63 weights per channel pair. Repeating dilation 2 samples only every second row and column, so about 72% of its 17×17 field never contributes. This is the gridding problem, and it is why schedules start at dilation 1 and grow.

Why not just pool and upsample?

Pooling throws away where things are, and segmentation needs exactly that. Earlier systems either pooled hard and then learned to upsample, or ran the network on several rescaled copies of the image. Dilation gives large context and full resolution at once. The front end applies the same idea to VGG-16. The last two pooling and striding layers are deleted, and the convolutions after each deleted pool get dilation 2 (then 4). That keeps the pretrained weights usable and gives 64×64 output maps. The paper also removed padding of intermediate feature maps, another leftover from classification.

Making the context module train

The module maps C feature maps to C feature maps, so it can drop into any dense-prediction network. Random initialisation didn't work. The fix was to initialise every layer to pass its input straight through: the filter's centre tap is 1 on the matching channel and every other weight is 0. Backprop then learns to add context on top. This is the same "start at the identity" idea as ResNet (Day 09, Day 10), arrived at independently for a different reason.

Limitations, and what came after

  • Memory. Keeping full resolution through deep layers is expensive in activations, which matters on small GPUs.
  • Gridding artefacts appear when large dilations follow each other. Follow-up work by the same group (Dilated Residual Networks, 2017) added layers to smooth them out.
  • The ideas spread fast. DeepLab's atrous spatial pyramid pooling runs several dilations in parallel. WaveNet and temporal convolutional networks use causal 1-D dilated convolutions to cover long time windows. Later, attention (Day 13) offered global context in one layer, at quadratic cost.

4. Why it matters for robotics

  • Segmentation drives grasping and navigation. Pick points, suction targets and drivable-terrain masks are per-pixel outputs. A model that keeps resolution gives tighter object boundaries, and that decides whether a gripper closes on the object or on the table.
  • Context fixes local ambiguity. A grey patch could be road or wall. Only a wide receptive field can tell. Dilated stacks give that context without a huge model.
  • 1-D dilated convs suit robot time series. Force/torque, IMU and joint histories need long windows at low latency. A causal dilated stack covers hundreds of timesteps with a few layers and runs in parallel, unlike an RNN.
  • Measure what matters. Evaluate with mean IoU and per-class IoU, not pixel accuracy. Practise both in Module 02's TensorTonic track (mIoU, Dice loss).

6. Self-check

How many weights does a 3×3 filter with dilation 4 have, and what span does it cover?

Still 9 weights per channel pair. It spans 9×9 pixels: 1 + 2·4.

What is the receptive field after 3×3 layers with dilations 1, 2, 4, 8?

1 + 2·(1 + 2 + 4 + 8) = 31 pixels across.

Why is dilation better than pooling for segmentation?

It grows context without lowering resolution, so you don't need to recover lost spatial detail with upsampling later.

What goes wrong with dilations 2, 2, 2, 2?

Only every second pixel is ever sampled, so the receptive field has holes. This is gridding.

Why identity initialisation?

Random init left the module unable to improve on its input. Starting from pass-through means the module begins harmless and learns to add context.
