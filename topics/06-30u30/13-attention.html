Attention Is All You Need

Drop the recurrence, keep the attention. Every token looks at every other token in one parallel step, and that turned out to scale better than anything before it.

AuthorsVaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin
Year / venue2017 · NIPS (NeurIPS)
Core ideaSelf-attention instead of recurrence
Study time4–6 h

Original: arXiv:1706.03762 · Code, notebook and exercises: 30u30 Day 13

Start here (no maths needed)

A Transformer lets every word in a sentence look at every other word at the same time, and decide which ones matter most for understanding it.

Think of it like this

Imagine you scroll back in a group chat and see the message "She said yes!" To understand it, you look back at the other messages to find out who "she" is and what the question was. You don't reread every message equally. You pay most attention to the few that help. In a Transformer, every word does this for itself, and all the words do it at once instead of waiting in a queue.

How it works

  1. The sentence is split into small pieces called tokens, usually words or parts of words.
  2. Each token makes a "question" (what am I looking for?) and a "label" (what do I have to offer?).
  3. Each token compares its question with every other token's label. Good matches get a bigger share of its attention. The shares always add up to 100%.
  4. Each token then mixes in information from the tokens it paid attention to. All tokens do this at the same time, which makes it very fast on modern chips.
  5. This is repeated in several layers, so the understanding gets deeper each time.

Why robots care

A robot looking at a table can treat each thing it sees as a token: the gripper, a cup, a plate, a toy. Attention lets it link "gripper" with "cup" when the task is "pick up the cup", without anyone writing special rules. Many modern robot brains are built from this exact block.

Try it

  • Read this sentence: "The trophy didn't fit in the suitcase because it was too big." What does "it" mean? Which word did you look back at to decide? That looking back is attention.

Words to know

Token
One small piece of the input, such as a word.
Attention
Deciding how much to focus on each other token.
Query, key, value
A token's question, its label, and the information it passes on.

A neural network built from attention layers, with no step-by-step memory loop.

1. Summary

TL;DR

Before 2017, the best translation systems were recurrent encoder–decoders with attention bolted on (Day 15). This paper kept only the attention, "dispensing with recurrence and convolutions entirely". The result, the Transformer, trained faster because every position is computed in parallel, and it set new translation records. Almost every large model since, from GPT and BERT to ViT and today's robot policies, is a variant of this block.

  • Building block: scaled dot-product attention. Each token emits a query, a key and a value. Output = a softmax-weighted average of the values.
  • Multi-head: run several smaller attentions in parallel so different heads can track different relations.
  • Layer: attention, then a small per-token MLP. Each wrapped in a residual connection plus layer norm. Stack 6 in the encoder and 6 in the decoder.
  • Order: attention ignores position, so sinusoidal positional encodings are added to the input embeddings.
  • Results: 28.4 BLEU on WMT 2014 English→German and 41.8 on English→French with the big model (213M parameters, 3.5 days on 8 P100 GPUs). The base model (65M) trained in 12 hours.
  • The 30u30 folder builds every piece from scratch, then a full Transformer, with five exercises.

2. The core idea

Pack the queries, keys and values of all tokens into matrices Q, K, V (one row per token):

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V

head_i      = Attention(X·W_i^Q, X·W_i^K, X·W_i^V)
MultiHead(X) = Concat(head_1, …, head_h) · W^O

FFN(x) = max(0, x·W_1 + b_1)·W_2 + b_2
x ← LayerNorm(x + Sublayer(x))      # after every sublayer
  • Q·Kᵀ is an n×n table of scores: how well token i's query matches token j's key.
  • /√d_k keeps the scores in a sane range (see the demo). d_k is the key width, 64 in the base model.
  • softmax runs along each row, so each token's weights over the others are positive and sum to 1.
  • ·V mixes the value vectors with those weights. Each output row is a blend of the tokens that row attended to.
  • W_i^Q, W_i^K, W_i^V are learned projections, one set per head. Base model: 8 heads of width 64, so d_model = 512. W^O maps the concatenated heads back to 512.
  • FFN is applied to each position separately, with an inner width of 2048.

Positions are injected once, at the bottom of each stack:

PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))

Each pair of dimensions is a sine/cosine at a different frequency, from fast to very slow. The authors chose this because a fixed offset k becomes a linear function of the encoding, which should make relative positions easy to learn. Learned position embeddings gave nearly identical results.

3. Deep dive

Why throw away recurrence

An RNN (Days 01–02) must process token 1 before token 2. For a sequence of length n that is n steps you can't parallelise, and information from the start must survive n state updates to reach the end. The paper's Table 1 compares layer types:

  • Self-attention: O(n²·d) work per layer, O(1) sequential steps, path length O(1) between any two tokens.
  • Recurrent: O(n·d²) work, O(n) sequential steps, path length O(n).

When n is smaller than d (true for sentences), attention is cheaper and fully parallel. The cost is the n² term, which is why long-context models later invented linear and hybrid attention. See Module 05 for how Kimi K3 mixes linear attention with full attention to reach a million tokens.

Three jobs for one mechanism

  • Encoder self-attention: every source token attends to every source token.
  • Decoder masked self-attention: each target token attends only to earlier target tokens. Future positions get a score of −∞ before the softmax, so generation stays autoregressive.
  • Encoder–decoder attention: queries come from the decoder, keys and values from the encoder output. This is the Bahdanau idea (Day 15) in dot-product form.

Multiple heads matter: in the paper's ablation, a single head was 0.9 BLEU worse than the best setting, and too many heads also hurt. At inference the decoder caches each layer's keys and values so old tokens aren't recomputed. That cache is the memory bottleneck that DeepSeek's MLA attacks in Module 05.

Why divide by √d_k

If query and key entries are independent with mean 0 and variance 1, their dot product has variance d_k. With d_k = 64 raw scores of ±8 or more are normal, and the softmax then puts nearly all weight on one key. Gradients through a saturated softmax are tiny, so learning stalls. Dividing by √d_k brings the variance back to 1 regardless of width.

Training recipe, in one paragraph

Adam with a learning rate that rises linearly for 4,000 warmup steps and then decays with the inverse square root of the step. Dropout 0.1 on each sublayer output. Label smoothing 0.1, which the authors note hurts perplexity but improves BLEU. Beam search of size 4 at test time. Day 14 turns each of these into running code. The same architecture also reached 91.3 F1 on English constituency parsing trained only on the WSJ data, a sign it wasn't tuned only for translation.

4. Why it matters for robotics

  • It is the backbone of robot foundation models. Vision-language-action models such as RT-2 are Transformers that read image patches and instruction tokens and emit action tokens. If you understand this block, you can read their architecture diagrams.
  • Action chunking uses the encoder–decoder form. ACT (the ALOHA policy) feeds camera features into a Transformer encoder and decodes a whole chunk of future joint targets at once with cross-attention, instead of one action per step.
  • Attention over objects and sensors. Treat each detected object, each camera, or each proprioceptive reading as a token. Self-attention then lets the policy relate "gripper" to "cup" without hand-coded features, and the weights are inspectable.
  • The n² cost is a real constraint on the robot. Long observation histories and many image patches blow up compute and KV-cache memory on an onboard GPU. That's why robot stacks shrink token counts, cache, or distil to small models (Module 04).

6. Self-check

What do Q, K and V each do?

The query says what a token is looking for. Keys say what each token offers to be matched against. Values are what actually gets mixed into the output once the weights are set.

Why scale the scores by 1/√d_k?

Dot products of random d_k-dimensional vectors have variance d_k. Large scores saturate the softmax, which makes gradients vanishingly small. Scaling restores unit variance.

Why does the Transformer need positional encodings at all?

Attention is a weighted sum over a set. Shuffle the input tokens and each output is just shuffled the same way. Without position signals, "dog bites man" and "man bites dog" look identical.

What does the decoder mask do, and why is it needed in training?

It sets scores for future positions to −∞, so token i can only see tokens up to i. Training feeds the whole target sentence at once, so without the mask the model could copy the answer.

When is self-attention more expensive than a recurrent layer?

When sequence length n exceeds the model width d, since attention costs O(n²·d) per layer and recurrence O(n·d²). Long contexts are where this bites.
