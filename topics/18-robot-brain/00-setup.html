Start here

A computer does exactly what you tell it, step by step, and nothing else. A list of exact steps is called an algorithm.

Terminal
A window where you type commands instead of clicking.
Function
A named block of code. It takes inputs and gives back an answer with return.
Loop
Code that repeats. while repeats as long as something is true.

1. The idea

💡 The idea

Write instructions for a jam sandwich and give them to someone who follows them exactly. "Put jam on the bread." They put the closed jar on the loaf. You never said "open the jar". A computer is that person. It isn't stupid, it's literal.

So a robot can't "just look" and see that the wall is 3 squares away. It has to look at the next square, step, and look again, counting as it goes:

Three things make a good algorithm: every step is exact, the order is right, and it stops.

Here is the room your robot lives in. It's a grid of squares: grey walls, three coloured blocks, a bin. By week 16, you type "put the red block in the bin" and it plans the route and does it.

3. Set up

🛠 Build: get Python working

Most people who give up on programming give up here, at setup. Go slowly. After every step there's a checkpoint: don't move on until yours matches.

  1. Install Python 3 (3.8 or newer). Open your system below.
    Windows

    Go to python.org → Downloads → the yellow button. Open the downloaded file. Before anything else, tick "Add python.exe to PATH" at the bottom of the first screen. Then click Install Now. On Windows, type py everywhere this course says python3.

    macOS

    Go to python.org → Downloads → "Download Python 3.x.x". Open the .pkg file and click through to Install. Always type python3, not python.

    Linux / Raspberry Pi

    Python 3 is almost always there already. If not: sudo apt install python3 (or sudo dnf install python3 on Fedora). Nothing shows while you type a password. That's normal.

  2. Open a terminal. Windows: press the Windows key, type powershell, Enter. Mac: Cmd+Space, type Terminal, Enter. Linux: Ctrl+Alt+T. Then type: 
    python3 --version          # Windows: py --version

    You see a version number. On our Mac it printed:

    Python 3.14.5

    Yours may differ. Anything from 3.8 up is fine. If you see "command not found" or "not recognized", Python isn't on the PATH: close the terminal, reopen it, and try again. On Windows, run the installer again, choose Modify, and tick "Add to PATH". If python opens the Microsoft Store, use py.

4. Build your first two functions

🛠 Build

Each function in lesson00_hello.py has a line raise NotImplementedError(...). It means "not written yet". Delete it and write your code in its place. Save before every run.

  1. introduce(name) returns (not prints!) the greeting. introduce("Robo") must give exactly "Hello, I am Robo!": comma, one space, exclamation mark.
    🆘 Stuck?
    Hint 1

    An f-string glues a value into text: f"I am {age} years old".

    Hint 2

    It's one line: return and an f-string with {name} inside it.

    Hint 3: fill in the blank
    return f"Hello, I am ____!"
    ✅ Checkpoint

    Run python3 check.py 0. Real output:

    Lesson 0: lesson00_hello.py
  ✓ introduce
  … steps_to_wall: not written yet (Lesson 0: write this function)
  1/2 passed

    If you see ✗ introduce: introduce("Robo") should return exactly "Hello, I am Robo!", check every character, and check you used return, not print.

  2. steps_to_wall(start_x, wall_x) is the corridor algorithm from the picture. Walk right one square at a time, stop on the square just before the wall, return the number of steps. Use a loop, not subtraction: a real robot doesn't know where the wall is until it looks. steps_to_wall(1, 5) → 3, steps_to_wall(4, 5) → 0.
    🆘 Stuck?
    Hint 1

    You need two variables that change: where the robot is (x) and how many steps it took (steps). Set both before the loop.

    Hint 2

    Keep going while the next square, x + 1, is less than wall_x.

    Hint 3: fill in the blanks
    steps = 0
x = start_x
while ____ < wall_x:
    x += 1
    steps += ____
return steps
    ✅ Checkpoint

    Run the lesson file:

    cd homework
python3 lesson00_hello.py
cd ..

    Real output:

    Hello, I am Robo!
Steps to wall: 3

    Then python3 check.py 0:

    Lesson 0: lesson00_hello.py
  ✓ introduce
  ✓ steps_to_wall
  2/2 passed  🎉 lesson complete!

    If you see ✗ steps_to_wall: steps_to_wall(1, 5) should be 3, you probably wrote while x < wall_x. That walks onto the wall. Trace it on paper.

How your robot file works. You'll fill in its gaps, so here are the four ideas it uses.
  • A class is a blueprint. class Robot: says what every robot knows and does. Robot() builds one.
  • A method is a function inside the class. arrows and look are methods.
  • self means "this robot". self.pos is where this robot is.
  • Helpers are ready for you. self.step(square) moves one square and says "moved", "stopped" or "bump".
class Robot:
    def where(self):
        return f"I am at {self.pos}."

If zippy.pos is (1, 1), zippy.where() returns "I am at (1, 1).". Python fills in self for you. Every gap is marked # TODO week N.

6. Real-world challenge: the literal friend

  1. Write 8–15 numbered steps for making a sandwich (blunt knife, ask an adult) or drawing a house.
  2. A friend follows them exactly, and does something silly whenever a step is vague.
  3. Write down each bug: vague, missing, wrong order, or never stops. Fix it and run again until there are no bugs.
On your own: write the steps for drawing a house, wait an hour, then follow them yourself as literally as you can.

Most people find 5–10 bugs in version 1. Testing finds bugs you can't see while writing. That's why this course has check.py.

Check yourself

Predict: what does steps_to_wall(3, 9) return?

5. x goes 3 → 4 → 5 → 6 → 7 → 8. At 8 the next square is the wall.

If introduce uses print and no return, what does x = introduce("Robo") put in x?

None. The text appears on screen, but nothing comes back.

Why use a loop instead of wall − start − 1?

Subtraction needs you to know where the wall is. A robot finds out by looking one square at a time. In week 2 that look becomes a sensor.

"can't open file 'check.py'". What's wrong?

The terminal is in the wrong folder. cd into project, the folder with check.py in it.

Want to know more?

Tracing: how professionals check a loop

Write every variable at every step. For steps_to_wall(1, 5):

x = 1, steps = 0   next is 2, not the wall → move
x = 2, steps = 1   next is 3 → move
x = 3, steps = 2   next is 4 → move
x = 4, steps = 3   next is 5, the wall → stop. Answer 3
Stretch: walk left

Write steps_to_wall_left(start_x, wall_x) for a wall on the left. Trace steps_to_wall_left(6, 2) on paper first. The checker doesn't test it.

Common mistakes
  • Printing instead of returning. The function gives back None.
  • Off by one. while x < wall_x gives 4 instead of 3.
  • Forgetting to save. The checker reads the file on disk.
  • Odd codes like [32m on old Windows terminals are harmless colours. PowerShell shows them properly.
