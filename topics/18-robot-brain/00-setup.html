A computer does exactly what you tell it, step by step, and nothing else. A list of exact steps is called an algorithm.

Grown-up help today: an adult helps install Python. The computer may ask for an admin password.

The problem

Robo-Helper lives in a room made of squares. Right now it can't do anything at all. It can't even say hello. It also can't work out how far it can walk before it bumps into a wall. You're going to give it both skills. But first you need a way to talk to it: Python, and a terminal.

The idea in one picture

Imagine writing instructions for making a jam sandwich, then handing them to someone who follows them exactly, word for word. "Put jam on the bread." They put the closed jar on top of the loaf. You never said open the jar, or use a knife, or which slice. A computer is that person. It isn't stupid. It's literal. Your job is to write steps so exact that even a literal follower gets it right.

Words to know

Algorithm
An exact list of steps that solves a problem. A recipe is a loose algorithm. Code is a strict one.
Terminal
A window where you type commands to your computer instead of clicking. Also called the command line, shell, Command Prompt or PowerShell.
Folder path
The address of a folder, like Documents/Learning robotics/topics.
Function
A named, reusable block of code. You give it inputs, it gives back an answer with return.
Loop
Code that repeats. while repeats as long as something is true.

Before any of that, you need Python working. Let's do setup first, carefully. Most beginners who give up on programming give up here, at setup, not at the code. So go slowly, and if something doesn't match what you see, read the "If it goes wrong" boxes.

Step A. Install Python 3

Python is the programming language we'll use. "Installing" it puts a program on your computer that reads your .py files and runs them. You need version 3.8 or newer. The newest one is fine.

If you're on a family or school computer, you may need a parent or teacher to type an admin password during install. That's normal.

Windows
  1. Open a web browser and go to python.org. Click Downloads. The site detects Windows and offers a big yellow button, "Download Python 3.x.x". Click it.
  2. Open the file you downloaded (it's in your Downloads folder, named something like python-3.x.x-amd64.exe).
  3. Before you click anything else: at the bottom of the first screen there is a checkbox labelled "Add python.exe to PATH" (older versions say "Add Python to PATH"). Tick it. This lets you type python in any terminal. Forgetting it is the number one setup problem on Windows.
  4. Click Install Now. Say yes if Windows asks for permission. Wait for "Setup was successful", then click Close.
  5. Check it worked (you'll learn how to open a terminal in Step B): type py --version and press Enter. You should see something like Python 3.13.1.
If it goes wrong on Windows: if typing python opens the Microsoft Store, Windows is using a shortcut instead of your install. Use py instead of python3 everywhere in this course (for example py check.py 0). If py isn't found either, run the installer again, choose Modify or Repair, and make sure "Add to PATH" is ticked. Then close and reopen the terminal.
macOS
  1. Go to python.org, click Downloads, and click "Download Python 3.x.x" (it detects macOS).
  2. Open the downloaded .pkg file and click Continue through the screens, then Install. Type your Mac password if asked.
  3. When it finishes, a Finder window opens. You can close it.
  4. Check it worked: open Terminal (Step B) and type python3 --version. You should see something like Python 3.13.1.
If it goes wrong on a Mac: if typing python3 pops up a box asking to install "command line developer tools", you can click Install. That also gives you a working python3. Always type python3, not python: on some Macs python doesn't exist.
Linux (Ubuntu, Debian, Fedora, Raspberry Pi OS…)
  1. Python 3 is almost always already installed. Open a terminal (Step B) and type python3 --version.
  2. If you see Python 3.8 or higher, you're done.
  3. If it says "command not found", install it. On Ubuntu, Debian or Raspberry Pi OS type sudo apt install python3. On Fedora type sudo dnf install python3. It asks for your password. Nothing appears while you type a password: that's normal, just type it and press Enter.

Step B. Open a terminal

  • Windows: press the Windows key, type powershell (or cmd), press Enter. A dark window with a blinking cursor appears.
  • macOS: press Cmd+Space, type Terminal, press Enter.
  • Linux: press Ctrl+Alt+T, or find "Terminal" in your apps menu.

The terminal shows a prompt, something like C:\Users\Sam> or sam@laptop ~ %. That tells you which folder you're "standing in" right now. You type a command after it and press Enter. Try typing python3 --version (on Windows, py --version).

2. First principles: what is an algorithm?

Steps, exact steps

An algorithm is a finite list of exact steps that, followed one at a time, solves a problem. Three things make a list of steps a good algorithm:

  1. Every step is exact. No "you know what I mean". "Spread some jam" is vague. "Use the knife to scoop one spoonful of jam and spread it over the top face of slice 1" is exact.
  2. The order is right. Open the jar before scooping.
  3. It stops. "Keep spreading jam" never ends. "Spread until the whole face is covered" does.

A computer is the perfect literal follower. That's both its superpower (it never gets bored, never skips a step) and its weakness (it never fills in the gaps for you).

Your first robot algorithm, on paper

Here's a corridor. The robot R stands on square 1. The wall is on square 5. Squares are numbered from 0, left to right:

square:  0   1   2   3   4   5
         .   R   .   .   .   #

The robot walks right, one square at a time, and must stop on the last free square, just before the wall. How many steps does it take?

A human just looks and says "3". But a robot can't "just look". It only knows where it is and can check one thing at a time. So write it as exact steps:

1. Set steps to 0. Set x to the start square.
2. Look at the next square, x + 1. Is it the wall?
3.   If it's NOT the wall: move there (x goes up by 1), add 1 to steps, go back to step 2.
4.   If it IS the wall: stop. The answer is steps.

Follow it by hand, like a computer would, writing down x and steps each time:

x = 1, steps = 0   next square is 2. Wall is 5. 2 is not 5 → move
x = 2, steps = 1   next square is 3. Not the wall → move
x = 3, steps = 2   next square is 4. Not the wall → move
x = 4, steps = 3   next square is 5. That's the wall → stop
answer: 3

This style of checking, writing every variable at every step, is called tracing. Professionals do it whenever code surprises them.

Predict first: the robot starts on square 4 and the wall is on square 5. What's the answer? Guess, then open.

0. Trace it: x = 4, steps = 0, the next square is 5, which is the wall, so stop straight away. The loop body never runs even once. This "do nothing" case is called an edge case, and it's where most bugs hide. The checker tests exactly this case.

Why not just subtract?

You might spot a shortcut: answer = wall − start − 1. For 1 and 5 that gives 3. Correct! So why does the homework say "use a loop, not subtraction"?

Because a real robot doesn't know where the wall is in advance. It only knows "is the square in front of me free?" Next lesson you'll replace "is it the wall square?" with a real check on the room map, and in Lesson 2 that check becomes a sensor. Subtraction only works when you already know the answer. The loop works when you have to find out. That's how robots think: look, move, look again.

Turning steps into Python

Each line of the paper algorithm becomes a line of Python:

Paper stepPython idea
Set steps to 0a variable: steps = 0
Repeat while the next square isn't the walla while loop with a condition
Move, and count itadd 1 to two variables: x += 1 means "x becomes x + 1"
Stop and give the answerreturn steps

4. Homework

Open homework/lesson00_hello.py in your editor. You'll see two functions. Each has a docstring (the text in triple quotes) that says exactly what it must do, and a line raise NotImplementedError(...). That line means "not written yet". Delete it and write your code in its place.

Function 1: introduce(name)

What it does: takes a name and returns (not prints!) the robot's greeting as a string.

Example: introduce("Robo") must give back exactly "Hello, I am Robo!". Capital H, a comma, one space after it, an exclamation mark at the end.

Hint 1

You need to glue the name into the middle of some fixed text. Python has a neat way to do that called an f-string.

Hint 2

An f-string starts with f before the quote, and anything inside { } is replaced by its value. f"I am {age} years old" becomes "I am 15 years old" when age is 15.

Hint 3

One line: return followed by an f-string that contains Hello, I am , then {name}, then !. Check the punctuation against the example character by character.

Function 2: steps_to_wall(start_x, wall_x)

What it does: the paper algorithm from section 2. Start at start_x, walk right one square at a time, stop on the square just before wall_x, and return how many steps that took. Use a loop, not subtraction.

Example: steps_to_wall(1, 5) → 3 (1 → 2 → 3 → 4, then the wall is next). Also steps_to_wall(4, 5) → 0, and steps_to_wall(0, 10) → 9.

Hint 1

You need two variables that change: where the robot is now, and how many steps it has taken. Set both up before the loop.

Hint 2

A while loop keeps going while its condition is true. The condition is "the next square is still before the wall". The next square is x + 1. "Before the wall" means less than wall_x.

Hint 3
steps = 0, x = start_x
while (next square) is less than wall_x:
    move x forward one
    add one to steps
return steps

5. Real-world challenge: the literal friend

You'll feel what it's like to be a programmer whose computer does exactly what you wrote.

  1. Pick a task that takes a minute: making a jam (or butter) sandwich, putting on a jacket, or drawing a house on paper. Use a blunt butter knife only, and ask an adult if you're using the kitchen.
  2. Write the instructions on paper, numbered, without your friend watching. Aim for 8–15 steps.
  3. Your friend follows them literally. Their job is to be a computer: do exactly what each line says, nothing more, and do something silly if a step is vague. "Put the bread on the plate" while the bread is still in the bag? The whole bag goes on the plate.
  4. Record every bug. For each step that went wrong, write: step number, what you meant, what they did, and what kind of bug it was: vague (unclear words), missing (a step you forgot), order (right step, wrong place), or never stops.
  5. Fix and run again. Write version 2 and repeat. Keep going until a run has zero bugs.

What to record: the number of bugs in version 1, version 2 and version 3, and which kind was most common. Most people find 5–10 bugs in version 1. What it teaches: computers aren't clever about what you meant. Precision is the whole job, and testing (your friend) finds bugs you couldn't see while writing. That's exactly why this course has check.py.

7. Common mistakes

  • Printing instead of returning. print(...) shows text on screen but gives nothing back, so the function returns None and the checker says introduce("Robo") should return exactly "Hello, I am Robo!".
  • Tiny text differences. "Hello I am Robo!" (no comma) or "Hello, I am Robo" (no !) are different strings to a computer. Literal, remember?
  • Off by one. Using while x < wall_x walks the robot onto the wall square and gives 4 instead of 3. The checker says steps_to_wall(1, 5) should be 3. Trace it on paper to see why.
  • Running from the wrong folder. check.py lives in project/, the lesson files in project/homework/. "can't open file" means you're in the wrong one.
  • Forgetting to save. The checker reads the file on disk, not what's in your editor. Save first.

8. Check yourself

In your own words, what makes a list of steps an algorithm?

Every step is exact, the order is right, and it's guaranteed to stop with an answer. "Make a sandwich" isn't an algorithm. A numbered list a literal friend can follow without guessing is.

Predict: what does steps_to_wall(3, 9) return? Trace it.

5. x goes 3 → 4 → 5 → 6 → 7 → 8, which is five moves. At x = 8 the next square is 9, the wall, so it stops.

Predict: if introduce uses print and no return, what does x = introduce("Robo") put in x?

None. The greeting appears on screen, but the function hands back nothing. Every Python function without a return returns None.

Why does the homework forbid subtraction for steps_to_wall?

Subtraction needs you to already know where the wall is. A robot finds out by checking one square at a time. The loop version still works when the corridor has unknown walls in it, which is exactly what Lesson 2 needs.

You type python3 check.py 0 and get "can't open file 'check.py'". What's wrong?

The terminal is in the wrong folder. Use ls or dir to see where you are, then cd into the project folder (the one that contains check.py).
