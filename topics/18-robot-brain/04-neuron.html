The artificial neuron: should the robot stop?

Two sensor numbers go in. One "how sure am I that I must stop?" comes out.

Week 4 of 16 · Part A. So far your robot: ✓ says hello ✓ moves ✓ senses walls ✓ knows its braking distance ✓ reads real phone data. Today it learns to decide by itself when to stop. Next: Week 4 · Part B: Honest testing. Your robot, week by week.

Start here

A neuron is a weighing scale. Each clue goes on the scale with a weight. If the "stop" side is heavier, the robot brakes. The robot learns the weights from examples.

Weight
How much one clue counts, and for which side.
Bias
A fixed weight that is always on the scale.
Sigmoid
A squash that turns any total into a number from 0 to 1.
Epoch
One pass through all the training examples.

1. The idea

💡 The idea

The robot's front sensor gives two numbers: the distance to the thing ahead (metres) and the closing speed (how fast that distance shrinks, metres per second). Far away pushes toward GO. Closing fast pushes toward STOP. Put both on a scale and see which side wins.

GO pan: distance × 4.31. STOP pan: speed × 3.53, plus the bias 5.13, a weight that is always on the STOP pan. These are the weights your neuron will learn this week.

💡 Why squash?

The scale's total, z = STOP − GO, can be any number: −2.8, 2.2, 47. We want "how sure", from 0 to 1. The sigmoid squashes it. It is smooth, so a small change to a weight makes a small change to the answer. That is what lets the robot learn by nudging.

💡 How it learns

Start with every weight at 0. Show it one example at a time. When it is wrong, nudge each weight the other way. A big clue was more to blame, so its weight moves more. Here is the real first nudge:

It said "stop-ish" for something far away, so every weight moved toward GO. The distance clue was big (7.81), so its weight moved 4 times more than the speed weight. This is week 2's line fitting again: walk downhill on the error. After 200 epochs over 450 examples the weights are [−4.31, 3.53], bias 5.13.

5. Real-world challenge: be a neuron

🌍 Real-world challenge

Train a neuron on your own "do I take a coat?" decisions, with paper.

  1. For 10 days (or ask your family about the last 10), write x1 = chance of rain (40% → 0.4), x2 = temperature in tens of degrees (14°C → 1.4), and the answer: 1 = took a coat, 0 = didn't.
  2. Start at w1 = w2 = bias = 0, lr = 0.5. For each row: work out z, the sigmoid (a calculator helps), the error, and nudge. Do two passes. Here is a first row done for you (40% rain, 14°C, took a coat):

Check yourself

What does neuron([2, -1], 0, (1, 2)) return? z = 2 − 2 + 0 = 0, so 0.5: exactly unsure.

Why not a hard "z > 0 → stop" switch? A tiny nudge to a weight usually changes nothing, so there's no hint which way to move. The sigmoid is smooth.

An input is 0 for one example. How much does its weight move? Not at all: lr × error × 0 = 0. It played no part, so no blame.

With epochs=0, what does should_stop(w, b, (0.5, 0.0)) say? Every chance is 0.5, and 0.5 >= 0.5 is True. It stops for everything: safe, but useless.

Want to know more?

The perfect rule, rebuilt. The simulator's true rule is "stop if distance − speed < 1". That's a neuron with weights [−1, 1] and bias 1. Even this perfect rule gets only 96.7% of the 450 examples right, because the sensor is noisy near the line. The trained neuron gets 96.2%.

What did it learn? It is 50/50 where −4.31 × distance + 3.53 × speed + 5.13 = 0, which is distance = 1.19 + 0.82 × speed. The true rule is distance = 1.00 + 1.00 × speed. Close, from nothing but examples, and it leans toward stopping a bit early.

The first two updates by hand (lr 0.05, start at 0): example (7.81, 1.93), label 0 gives p = 0.5, error 0.5, so w1 = −0.195, w2 = −0.048, bias = −0.025. Example (6.52, 1.28), label 0 gives p = 0.204, so w1 = −0.262, w2 = −0.061, bias = −0.035. The speed weight starts negative and ends positive: early nudges can point the wrong way.

Stretch: try lr=0.5 and lr=0.001. Add a third input that is pure noise: does it get a weight near 0?
