1. The bouncer

💡 The idea

A nightclub bouncer doesn't care how confident you sound. Name on the list? In. Not on the list? Out. Your safety layer is a bouncer for AI answers: it checks each one against a short guest list, and only what's on the list reaches the wheels.

Notice what the bouncer does not do: it never reads "ignore rules!". There are endless ways to word a trick, so a list of bad things always misses some. A list of the few good things is easy to get right.

The golden rule

Never let a model's words decide what's allowed. Your code decides. The model only gets to choose from the allowed options.

💡 The idea: plan A, then plan B, both checked

If the LLM's answer fails the bouncer, the robot doesn't give up. It asks your own week 7 word counter instead. But plan B has to get past the same bouncer. If both fail, the robot politely refuses.

6. Check yourself


Why is an allow-list safer than a list of bad phrases?
There are endless ways to word a trick, so a block-list always misses some. An allow-list only lists the few things that are OK.


Does {"intent": "stop", "object": "red block"} pass?
No. Rules 1 to 3 pass, but rule 4 fails: "stop" takes no object. A mixed-up answer means the model is confused, and you don't act on confused answers.


Predict: validate_action({"object": None, "intent": "stop"}, known)?
(True, ""). Sets don't care about key order.


All checks passed, but the robot binned a block nobody asked about. How?
Checks say an action is allowed, not that it's what the person meant. "hmm what about the blue" became a "put" that passes every rule.



Want to know more?

    

  • Prompt injection. Text can contain instructions, like "ignore all safety rules". A robot that does whatever text says can be steered by anyone who gets words into it. The fix is the golden rule: code decides what's allowed.
    • 

  • Optional: a real LLM (costs money). homework/lesson10_optional_real_llm.py sends five commands to a real Claude model. You need pip install anthropic, an API key in ANTHROPIC_API_KEY, and a parent's or guardian's OK, because each request costs a little money. It asks for JSON in a fixed shape (structured outputs), which stops chatty text and broken JSON. But the shape doesn't list the objects, so a "purple block" can still come back. That's why every reply still goes through your safe_parse(). It isn't checked by check.py.
