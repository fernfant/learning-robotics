A big model over the internet understands almost anything. But it's a guest in your robot. You tell it the rules, you describe the room, and you check everything it asks the robot to do.

Your tiny LM can't do "put away the block that's closest to the bin": it only reads words and has never seen the room. A huge model can, if you tell it what's in the room.

API key
A secret password that proves a request is yours. Each request costs money, so guard it like a bank card.
System prompt
The rules sent with every request.
Planner
One request in, one whole plan out. Then the robot runs it.
Agent
The model uses the robot's tools one at a time, seeing each result.
Tool call
The model asking your program to run one tool. Your program decides.

1. The idea

💡 Planner vs agent

Imagine phoning a world-famous chef. Planner: you describe your kitchen, they read out the whole recipe, you hang up and cook. Quick and cheap, but if the oven is broken, the recipe doesn't know. Agent: you stay on the phone. "Open the fridge." "Done, there's no milk." "Then use water." Slower, but it reacts to what happens.

Either way, the model never touches the robot. It only writes text. Your code decides what happens.

💡 What goes into a request

Calling Claude just sends a bundle of text to Anthropic's computers and gets text back. The bundle holds:

  • The rules (the system prompt SYSTEM): you are Robo-Helper; you may only put, go, find or stop; ask one question if unsure; never invent objects.
  • The room, from robot.look(). The model can't see your room, so you describe it. Real output on a fresh robot:
Robot at (1, 1), holding nothing. Bin at (7, 6). Blocks not yet in the bin: {'red block': (2, 1),
'blue block': (6, 3), 'green block': (1, 5)}. In the bin: nothing. Obstacles seen so far: none.
  • The shape of the answer (a JSON schema): {"reply": text, "clarify": a question or null, "plan": [actions]}. That makes the reply checkable by a program.

A schema fixes the shape, not the sense. It still allows a 40-step plan, or a question and a plan at once. So you check every reply. And the key? Never in your code. An adult puts it in an environment variable (ANTHROPIC_API_KEY), and anthropic.Anthropic() finds it by itself.

5. Real-world challenge: phone a chef


🌍 Real-world challenge

You need three people: a model in another room who can't see, a robot, and you, the checker. Put three objects and a box on the floor. Write a slip describing where everything is (that's look()). Allowed instructions: look, go to X, pick up X, put in box.


    

  1. Planner round: the model writes the whole plan for "put two things away, but not the one nearest the door". You check it; the robot follows it exactly. Just before they start, secretly move one object.
    2. 

  2. Agent round: reset, same secret move. Now one instruction per slip, and the robot writes back what happened.
    3. 



Record success, time and number of slips for each round.


On your own: be all three. Write the whole plan, close your eyes and move one object, then follow the slip exactly. Then redo it one instruction at a time, checking each against the four allowed tools.


The planner is quick but breaks when the world changes. The agent copes, with more slips. And in both, the person who could stop a mistake was the checker.





6. Check yourself


Why does the request include robot.look()?
The model can't see the room. Without it, it would guess, and a model guesses confidently instead of raising an error.


The API already forces the reply into a schema. Why write validate_plan?
The schema fixes the shape, not the sense: any length of plan, or a question plus a plan, still fits. The model can also send nothing. Never trust, always check.


validate_plan({"reply": "ok", "clarify": "", "plan": [put red]}, known): pass or fail?
Pass. An empty string is "falsy", so there's no real question.


"put the red and blue blocks away": how many requests for a planner? For an agent doing one tool per turn?
Planner: 1. Agent: look, then go_to, pick_up, put_in_bin for each block is 7 tool calls, plus one final turn saying "done": 8 requests.

Setting up with a key (for the adult)

Install the package in a virtual environment, as the project README shows:


python3 -m venv ~/robo-venv
source ~/robo-venv/bin/activate
pip install anthropic


Add export ANTHROPIC_API_KEY=... to ~/.zshrc and set a spending limit on the account. Never put the key in a code file or a chat. Then try python3 sim.py "put the block away" --brain planner or python3 sim.py "tidy up the room" --brain agent --watch. python3 brains.py record records runs so the replay brains and the bake-off can use them without a key.




What does a request cost?

The file uses $4 per million input tokens and $20 per million output for claude-opus-5-5. A made-up example: 1,000 tokens in and 200 out is $0.004 + $0.004 = $0.008. An agent re-sends the growing conversation every turn, so it costs more.
