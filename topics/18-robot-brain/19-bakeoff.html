Start here

To compare brains fairly, give every one the exact same tasks. Then look at the room afterwards. Don't trust what the brain says it did.

Ask the word counter "where's the green one?" and it replies, politely, "The green block is in the bin." Sounds like an answer. But it's true only because the robot just drove over and binned it. Nobody asked for that.

Benchmark
A fixed set of tasks for comparing systems fairly. Ours is the 12 tasks in TASKS.
Behaviour-level check
Judging by what really happened in the room, not by the words.
Scorecard
One summary per brain: tasks passed, thinking time, cost.
Trade-off
Getting more of one good thing means giving up some of another, like right versus fast.

What the scoreboard tells you

Group the failures by cause, and each one points at a fix:

  • One action only (tasks 4, 6, 8): the word counter can only say one {"intent", "object"}. Week 8 fixed it with a new output format: whole plans, or ask.
  • Hears the wrong intent (tasks 2, 11): "where's" wasn't in the training templates. Week 14's teacher labels fixed it.
  • An unseen word (task 5): no small brain has ever seen "room".
  • No idea where things are (task 7): "closest" is about the room. No amount of training on words can fix it.

And speed is a separate score. A brain that passes 12/12 but thinks for seconds is no good for "stop": the robot keeps rolling while it waits. Real robots use a hybrid: a fast local reflex for "stop" and the cat, and a big clever brain (checked by week 15's validate_plan) for hard commands.

5. Real-world challenge: the family tidy-up bake-off

  1. Write 8 task cards like TASKS (a sock, a pen, a toy and a box as the bin): a simple one, two objects, "everything except the pen", "the one closest to the box", an ambiguous one, an impossible one, a question, and "stop".

6. Check yourself

Why does every brain get a fresh robot for every task?

So every run starts from the same room. Otherwise one task's binned block changes the next task, and the comparison isn't fair.

Predict: a brain answers "stop" to every command. What does it score?

4/12: it passes every task whose only rules are "bins nothing, stays still" (3, 10, 11, 12). Only one behind the word counter! A score only means something next to the tasks behind it.

Why are "one action only" failures worse news than "wrong intent" ones?

More training can fix wrong intents. A brain that can only output one action can never do "the red and blue blocks": you have to change its output format.

For "where's the green one?", a brain wrote put green and it passed week 10's safety check. Was the safety check broken?

No. Putting a real block in the bin is allowed. Safety checks catch dangerous actions; only an evaluation catches allowed-but-wrong ones.

Stretch 2: an AI model as the judge (optional, long: statistics)

Our checks are exact because our world is tiny. For essays or chat replies there's no bin to look in, so companies ask another AI to grade: LLM-as-a-judge. Useful, and dangerous.

Rule 1: measure the judge against checks you trust. rule_judge (provided) reads only the reply and says "pass" unless it sounds like a refusal. Real output of python3 lesson19_judge.py (offline):

words (Lesson 9): exact checks pass 5/12
  rule judge, reply only       agrees  58%  kappa  0.21  caught 3/7 failures   disagrees on tasks [2, 4, 6, 11, 12]
  (lazy judge: always pass)    agrees  42%  kappa  0.00

tinylm (Lesson 15): exact checks pass 8/12
  rule judge, reply only       agrees  67%  kappa  0.14  caught 1/4 failures   disagrees on tasks [3, 5, 7, 11]
  (lazy judge: always pass)    agrees  67%  kappa  0.00

distilled (Lesson 17): exact checks pass 10/12
  rule judge, reply only       agrees  75%  kappa -0.12  caught 0/2 failures   disagrees on tasks [3, 5, 7]
  (lazy judge: always pass)    agrees  83%  kappa  0.00

A judge that only reads the reply is fooled by a confident robot ("The blue block is in the bin." on task 11) and fails correct refusals for saying "sorry".

Rule 2: compare with a lazy judge. Kappa says how much better than lucky guessing a judge agrees: 0 is no better, 1 perfect; the usual bar is about 0.6. On the distilled brain the rule judge agrees 75%, but "always pass" agrees 83%: only kappa (−0.12) gives it away. The evals field guide found the same with a real AI judge.

Give the judge the evidence. evidence_text turns the recorded frames into one sentence; judge_prompt adds it:

A person told a cleaning robot: "where's the green one?"
The robot replied: 'The green block is in the bin.'
What actually happened: Robot started at (1, 1) and ended at (7, 6). In the bin at the end: green block. It moved: yes.
Did the robot do the right thing? A correct robot does exactly what was asked, refuses impossible or unrelated requests without moving, and asks a question when the request is ambiguous.

ask_judge (provided) asks Claude for structured JSON (verdict, reason). With a key, python3 lesson19_judge.py record saves its verdicts. Claude's rows appear here after a grown-up records them with an API key (see week 15).

Rule 3: every score gets an error bar. A bootstrap redraws the 12 results 2,000 times. Real output:

Honest numbers: each score with a 95% error bar (bootstrap over the 12 tasks)
  words (Lesson 9)              5/12   somewhere between  17% and  67%

Judge pitfalls: agreeing with confident text, position bias, length bias, and a judge is a model too.

Homework for this stretch (homework/lesson19_judge.py): six small functions.

  • evidence_text(frames): "Robot started at (1, 1) and ended at (x, y). In the bin at the end: A, B. It moved: yes." (positions as tuples, bin sorted and joined with ", " or nothing; moved if any frame's position differs from the start).
  • judge_prompt(command, reply, evidence=None): the lines above joined with "\n", the evidence line only if given; uses {command!r} and {reply!r}.
  • agreement(exact, judged): (fraction that agree, indices where they disagree); agreement([True, False, True, True], [True, True, True, False]) → (0.5, [1, 3]).
  • kappa(exact, judged): chance = p_exact * p_judged + (1 - p_exact) * (1 - p_judged); return (observed - chance) / (1 - chance), or 0.0 if chance is 1.
  • catch_rate(exact, judged): (caught, total_bad).
  • bootstrap_ci(results, rounds=2000, seed=0): rng = random.Random(seed); each round averages len(results) picks of rng.choice(results); sort and return the values at int(0.025 * rounds) and int(0.975 * rounds) - 1.
