Start here (no maths needed)

micrograd is a little program that remembers every sum it does, so that afterwards it can tell you which number to nudge, and which way, to make the answer better.

Think of it like this

Imagine a row of dominoes that split and join. You push the first ones and the last one falls. Now you want to know: "if I had pushed domino 3 a bit harder, how much faster would the last one fall?" micrograd keeps a map of which domino knocked over which. Then it walks the map backwards, from the last domino to the first, and works out how much each one mattered. That backwards walk is called backpropagation.

How it works

  1. Every number is wrapped in a little box called a Value.
  2. When you add or multiply two boxes, the new box remembers which boxes made it, and how.
  3. At the end you have one number, the "loss", that says how wrong the answer is.
  4. Call backward(). micrograd walks the map backwards and writes into every box how much it changed the loss. That's its gradient.
  5. Nudge every weight a little bit against its gradient. The loss goes down. Repeat.

Why robots care

In Lesson 4 you worked out by hand how to change Robo-Helper's stop-detector weights. That works for one neuron. A brain with 100 or a million weights needs a machine to do it. micrograd is that machine, small enough to read in an afternoon.

Try it

  • In the demo below, drag the distance slider and watch the gradient of each weight change sign.
  • Write down a = 2, b = 3, c = a × b. If you add 1 to a, how much does c change? (It changes by 3, which is b. That's the gradient of c with respect to a.)

Words to know

Gradient
How much the loss changes if you nudge one number up a tiny bit.
Backpropagation
Walking backwards through the sums to get every gradient in one go.
Autograd
Software that does backpropagation for you, automatically.
MLP
"Multi-layer perceptron": layers of neurons, each layer feeding the next.
Loss
One number that says how wrong the model is. Smaller is better.

Going deeper: everything below is the full version, with some code and maths. On a first read, skim the headings, look at the demo and the Robo-Helper results, and come back for the rest later.

1. Summary

TL;DR

micrograd is a scalar autograd engine (engine.py, 94 lines) plus a tiny neural-network library on top (nn.py, 60 lines). Each Value stores a number, its gradient, its parents, and a small function that knows the local derivative. backward() sorts the graph and applies the chain rule from the output back to the inputs. We ran the README example (24.7041, 138.8338, 645.5773, as promised) and trained the README's 2-layer MLP on two moons: 100% training accuracy in 100 steps, 74.5 s on a MacBook CPU.

  • Everything is a scalar. A neuron is chopped into single adds and multiplies. That is slow, but every step is visible.
  • The API copies PyTorch. loss.backward(), p.grad, zero_grad() mean the same thing in both.
  • It checks out against PyTorch. The two unit tests compare micrograd's gradients with PyTorch's. Both passed on our Mac.
  • Robo-Helper result: on Lesson 4's own data a micrograd MLP is no better than the single neuron, because the true rule is a straight line. On braking data with a curved rule it misses 7 stops instead of 17, out of 500 test readings.
  • The README now points onward to microgpt, a whole GPT in one dependency-free Python file built on a faster version of this engine.

2. How the code works

The Value box

A Value holds data (the number), grad (starts at 0), _prev (the Values that made it) and _backward (a small function). Here is multiplication, quoted from engine.py:

def __mul__(self, other):
    other = other if isinstance(other, Value) else Value(other)
    out = Value(self.data * other.data, (self, other), '*')
    def _backward():
        self.grad += other.data * out.grad
        other.grad += self.data * out.grad
    out._backward = _backward
    return out

From karpathy/micrograd, micrograd/engine.py (MIT).

Read the two grad lines as: "if out moves by 1, self was pushing it with strength other.data". That is the derivative of a × b with respect to a, which is b. It's multiplied by out.grad, how much out matters to the final loss. That multiplication is the chain rule.

Notice the +=. If one Value is used twice (like b in the README example), the gradient from each use is added up. Forgetting this is the most common bug in hand-written backprop.

The one idea that makes it click: walk the graph backwards, in order

backward() first builds a topological order: a list where every Value comes after the Values that made it. Then it sets the output's gradient to 1 and calls each node's _backward in reverse order:

self.grad = 1
for v in reversed(topo):
    v._backward()

From karpathy/micrograd, micrograd/engine.py (MIT).

Reverse order guarantees that by the time a node passes its gradient back to its parents, it has already collected the gradient from everything that used it. That's the whole algorithm. PyTorch does the same thing, but on big arrays (tensors) instead of single numbers, and with fast C++ and GPU code.

The neural-network layer

nn.py builds on that: a Neuron is a list of weight Values and a bias, giving relu(w·x + b). A Layer is a list of Neurons, and an MLP is a list of Layers. parameters() collects every weight so the training loop can do p.data -= lr * p.grad. The demo's MLP(2, [16, 16, 1]) has 337 parameters.

DataWhat happened
Lesson 4/5 dataNo real gain. The true rule (d − v < 1) is a straight line, which is exactly what one neuron draws. The MLP's extra accuracy is one reading out of 150, and it misses one more stop. At Lesson 5's safe setting it is much worse: precision 0.500 against 0.837. Two more training seeds gave the same picture (safe-cut precision 0.837 and 0.818).
Braking dataA real gain. Stopping distance grows with speed squared, so the true boundary is a curve. A straight line can't follow it. At the default cut the MLP misses 7 stops instead of 17. At the same safe recall (0.958) its precision is 0.941 against 0.811, so it gives far fewer false alarms. Seeds 1 and 2 reached 0.972 and 0.974 accuracy, against the neuron's 0.946.

For this test we made the braking data ourselves. Speeds go up to 3.5 m/s, and the sensors are less noisy than Lesson 4's (0.1 m and 0.05 m/s). With Lesson 4's noisier sensors, the noise blurred the curve and the two models tied. Cost: in micrograd one MLP decision took about 0.2–0.5 ms, against 0.0005 ms for the neuron. In the simulator's bake-off the stop detector is trained on Lesson 4's straight-line data, so swapping in the MLP would not be expected to help there.

6. Why it matters for robotics

  • Every learned robot controller is trained by backprop. Policies, perception networks and world models all use this same algorithm, run by PyTorch or JAX on tensors.
  • Physics is often curved. Braking distance grows with speed squared. Torque needed changes with arm angle. Our braking test shows that one neuron can't draw these boundaries and a small MLP can.
  • Gradients can run through a simulator. "Differentiable physics" research builds simulators out of operations like micrograd's, so a gradient can flow from "the robot missed the target" back to the control inputs. micrograd shows the mechanism, not a tool you'd use for that.
  • Gradient checking is a safety habit. Before trusting a hand-written gradient in robot code, compare it against autograd or a numerical estimate, as we did above.

7. Reality check

  • Far too slow for real use. 74.5 s for 100 steps of a 337-weight net on 100 points. Real work uses tensors: PyTorch, JAX or tinygrad (page 5).
  • Only a few operations. +, ×, ** with a number, and relu. No exp or log, so no sigmoid or cross-entropy. That's why the demo uses a hinge loss. Our 27-line class adds exp and log.
  • Deep recursion. build_topo is recursive. A very long chain of operations can hit Python's recursion limit.
  • Not deprecated, but not the newest. The README sends readers who want more to microgpt, which keeps local gradients at forward time instead of one closure per operation.
  • Pitfalls when copying it: forgetting zero_grad() between steps (gradients pile up because of +=), and using = instead of += in a _backward.

8. Self-check

Why does _backward use += and not =?

A Value can feed several later operations. Its total gradient is the sum of the gradients from every use, so each use adds its share.

Why must backward() visit nodes in reverse topological order?

A node can only pass its gradient back once it has received gradient from every node that used it. Reverse topological order guarantees all of those come first.

In c = a × b, what is a.grad after c.backward()?

b.data. The output's gradient is 1, and the local derivative of a × b with respect to a is b.

Why didn't the MLP beat the single neuron on Lesson 4's data?

The true stop rule there is a straight line, which one neuron can already draw. Extra layers only help when the boundary is curved, as in the braking test.

What is the difference between micrograd and PyTorch's autograd?

The same algorithm. micrograd works on single numbers in pure Python. PyTorch works on whole tensors with fast compiled kernels on CPU or GPU.
