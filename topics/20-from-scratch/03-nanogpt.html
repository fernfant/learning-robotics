Start here (no maths needed)

nanoGPT is the same kind of brain as ChatGPT, shrunk down so small that you can train it on a laptop in under a minute and watch it learn to write like Shakespeare.

Think of it like this

Imagine a class reading a play aloud, one letter at a time. Before each new letter, every student looks back at the letters already read and decides which ones matter right now. One student watches for spelling. Another watches for whose turn it is to speak. Another watches for the end of a line. Then they pool what they noticed and guess the next letter. nanoGPT works like that class. Each "student" is called a head, and there are several rows of students, one row on top of another, called layers.

How it works

  1. Turn every letter into a list of numbers (an embedding), and add a second list that says where the letter is in the line.
  2. Each layer lets every letter look back at the letters before it (never ahead: that would be cheating) and pick out what's useful.
  3. After a few layers, the model gives a score to every possible next letter.
  4. Training compares that guess to the real next letter and nudges every number a little. PyTorch works out the nudges automatically.
  5. To write, it picks a letter, adds it to the end, and repeats.

Why robots care

The robot brains in the news (models that read a camera picture and a command, then output moves) are built from this same block: attention plus layers. If you can read nanoGPT's model.py, you can read the core of most of them.

Try it

  • Read the sample text in Run it, tested. It took 38 seconds of training. Which things did it already get right (names in capitals, a colon after the speaker)? Which words are made up?
  • Write a line, then try to guess the next letter of a friend's line from just the last 3 letters. Then from the last 30. More looking back means better guesses. That's why nanoGPT's "context" matters.

Words to know

GPT
A kind of language model built from stacked Transformer blocks that guesses the next token.
Token
One piece of text the model reads. In the Shakespeare demo, one token is one character.
Attention head
One "student" deciding which earlier tokens to look at.
Causal
Only allowed to look backwards, at tokens already written.
Loss
A score for how wrong the guesses are. Lower is better.
Validation (val) loss
The loss on text the model never trained on. It tells you if it learned or just memorised.

1. Summary

TL;DR

nanoGPT is a rewrite of minGPT that, in the README's words, "prioritizes teeth over education": it is meant to train real models fast. model.py defines GPT-2 (and can load OpenAI's GPT-2 weights). train.py is one training loop that runs on a laptop or, with the README's settings, reproduces GPT-2 (124M) on OpenWebText in about 4 days on an 8×A100 40GB node. On this M4 MacBook, the README's laptop-sized Shakespeare model trained in 38 seconds on MPS to a val loss of 1.8857.

  • Two files do the work. The model (embeddings, Transformer blocks, output head) and the training loop (batches, AdamW, learning-rate schedule, checkpoints).
  • Autograd does the calculus. Unlike our Module 18 lessons, there is no hand-written backward pass. One call, loss.backward(), computes every gradient.
  • Configs are just Python files plus --key=value flags that override them. No framework.
  • It scales by changing numbers, not code. The same files train a 0.8M-parameter toy and the 124M-parameter GPT-2.
  • As a Robo-Helper brain (61K parameters, the same training data as Lesson 15), it scored 9/12 in the bake-off against tinylm's 8/12. It kept the colour in 100% of commands with 14 filler words, against 52%, and decided in under 2 ms on the CPU. Details.
  • It's deprecated. The Nov 2025 note says you probably want nanochat, which covers tokenizer, pretraining, finetuning, evaluation and chat.

2. How the code works

model.py: the GPT

The model is four small classes and one big one:

  • CausalSelfAttention: one linear layer makes a query, key and value for every token, for every head at once. The tokens are split into n_head groups, each head does attention on its own slice, and the results are glued back together.
  • MLP: two linear layers with a GELU between them. The middle is 4× wider than the embedding.
  • Block: layer norm → attention → add back; layer norm → MLP → add back.
  • GPT: token embeddings (wte) plus position embeddings (wpe), a stack of n_layer Blocks, a final layer norm, and lm_head, which turns each position into a score for every token in the vocabulary.

The whole Transformer block fits in two lines. This is the one idea that makes it click:

# model.py (MIT, Andrej Karpathy): class Block
def forward(self, x):
    x = x + self.attn(self.ln_1(x))
    x = x + self.mlp(self.ln_2(x))
    return x

Each sub-layer only adds a correction to x; it never replaces it. That "add back" is the residual connection. Gradients can flow straight down the x = x + … path, which is why you can stack many blocks and still train them. Layer norm (ln_1, ln_2) rescales the numbers going into each sub-layer so they stay in a sensible range.

Inside attention, the line that makes it "causal" asks PyTorch's fused attention to mask out the future:

# model.py: CausalSelfAttention.forward (trimmed)
q, k, v = self.c_attn(x).split(self.n_embd, dim=2)
y = torch.nn.functional.scaled_dot_product_attention(q, k, v, attn_mask=None,
        dropout_p=self.dropout if self.training else 0, is_causal=True)

The file also keeps a slow, written-out version (used only on old PyTorch): q @ k.transpose, times 1/√(head size), fill the future with −∞, softmax, then @ v. That's exactly the recipe from our Lesson 15 stretch, done for every position and every head in one matrix multiply.

Two more details worth spotting: the output head shares its weights with the token embedding (wte.weight = lm_head.weight, "weight tying"), and generate() is a plain loop: crop to block_size, run the model, take the last position's scores, divide by temperature, optionally keep the top k, softmax, sample, append.

train.py: the loop

  1. Config. Defaults at the top of the file, then a config file, then command-line flags (via the tiny configurator.py), each overriding the last.
  2. Data. get_batch memory-maps train.bin (a long list of token ids as 16-bit integers), picks batch_size random start points, and takes block_size tokens from each. The targets are the same slices shifted by one.
  3. Learning rate. get_lr warms up linearly for warmup_iters, then follows a cosine curve down to min_lr at lr_decay_iters.
  4. Step. Forward, loss.backward(), clip the gradient norm to 1.0, AdamW step, zero the gradients. Gradient accumulation lets a small GPU fake a big batch.
  5. Evaluate. Every eval_interval steps, average the loss over eval_iters batches of train and val data, and save a checkpoint if val improved.
  6. Scale up. The same file runs on 8 GPUs with PyTorch DDP via torchrun, and can use torch.compile and bfloat16 on GPUs.

3. Run it, tested

All commands were run on 7 Nov 2026 on a MacBook (Apple M4, 16 GB), Python 3.14.5, in a private venv in a scratch folder. PyTorch reported torch.backends.mps.is_available() == True. train.py uses relative paths, so it is run from inside the cloned folder, as the README does.

4. The successor: nanochat

The nanoGPT README now opens with this: nanoGPT has "a new and improved cousin called nanochat", and "it is very likely you meant to use/find nanochat instead". nanoGPT only covered pretraining. nanochat (karpathy/nanochat, MIT, Oct 2025) covers the whole pipeline in one small codebase:

  • Stages: tokenizer training (a GPT-4-style BPE), pretraining, supervised finetuning (SFT), reinforcement learning, evaluation (CORE score, ARC, GSM8K, MMLU, HumanEval) and inference with a KV cache, plus a chat CLI.
  • One dial: --depth, the number of layers. Width, heads, learning rates, training length and weight decay are all calculated from it. GPT-2 capability is around depth 24–26.
  • Cost: the README says you can train a GPT-2-capability model "for only $48 (~2 hours of 8XH100 GPU node)" and then talk to it. At about $3 per GPU per hour, an 8×H100 node is about $24 an hour. On a spot instance it can be closer to $15. GPT-2 cost about $43,000 to train in 2019.
  • The "time to GPT-2" leaderboard: the main metric is the wall-clock time to beat GPT-2's CORE score (0.256525) on one 8×H100 node. The original OpenAI GPT-2 sits at 168 hours. The first nanochat entry (29 Jan 2026) took 3.04 hours. The newest entry in the saved README is 1.65 hours (14 Mar 2026, "autoresearch round 2"), after changes such as fp8, a 1M-token batch and a new dataset (NVIDIA ClimbMix).
  • On a Mac: runs/runcpu.sh trains a heavily shrunk model on CPU or MPS in a few tens of minutes. The README warns "You will not get strong results in this way." We did not run nanochat for this page.

Measured on 8 Nov 2026, with the first version of Robo-Helper's training data: 350 examples, which by accident included 3 of the 12 bake-off commands. On 9 Nov those were removed (343 examples). The experiment: swap Robo-Helper's brain for a nanoGPT

We used nanoGPT's model.py unchanged, at a small size: 2 layers, 4 heads, 48 channels, a 24-word window, 61,488 parameters. Each word is one token. A training example looks like command words <sep> plan words <end>, and the loss only counts the plan words. It trains on exactly the same data as the Lesson 15 model, lesson15_tiny_lm.training_data() (350 examples), and runs inside the same TinyLMBrain wrapper. That means the same typo fixer and the same Lesson 10 safety check on every action. We added one trick: in training, each example is shifted right by a random number of padding tokens, so every position learns to hold real words. Training 1,500 steps of batch 32 on the CPU took about 14 s per model. We trained 3 seeds.

What got better, and what didn't

  • Bake-off: 9/12 against 8/12 for tinylm and attention trained on the same data. With the teacher's labels it reaches 10/12, the same as the distilled brain, not better.
  • The extra pass is task 11, and it's luck. On "hmm what about the blue" the model wrote go blue green, which isn't a valid plan, so the robot stayed put and the task (bin nothing) passed. That's a safe failure, not understanding.
  • Buried colours: the clearest win. With 14 filler words, nanoGPT still found the colour 100% of the time, against 52% for both Lesson 15 models. Attention over every position, plus position embeddings, keeps the colour from being averaged away. The random padding in training helps too: without it, positions 15–18 would never have seen a real word.
  • Held-out test: 94% for two seeds and 88% for the third. That's level with the attention model, not ahead of it.
  • Still failing: "tidy up the room" (it asks "which block?") and "the block that's closest to the bin" (it says it can't). Neither is in the training templates, and no model this size can work out "closest" without seeing the room.
  • Speed: nanoGPT is about 5–8× slower than our pure-Python tinylm, because PyTorch has a fixed cost per call. On the Mac GPU (MPS) it is slower again, about 5 ms, because launching GPU work costs more than the sums themselves. Even so, the slowest case, 6.45 ms (8.6 ms for a 3-word plan), is far inside the 0.2 s "stop!" budget from Lesson 16. The robot rolls less than 1 cm while it thinks.

So nanoGPT is the next rung up. It isn't magic on 350 examples. What it adds is robustness to long, messy commands and a way to scale: the same file trains a 61K model in seconds or a 124M GPT-2 on a GPU node, just by changing numbers. Our hand-built model would need new hand-written backprop for every change.

Next-step exercise. Open nanogpt_brain.py and make the model bigger (n_layer=4, n_embd=96). Then remove the random padding by setting k = 0 in _example. Re-run it and record three numbers each time: bake-off score, filler accuracy at 14 words, and CPU p95. Which change matters more for the buried colours: the size or the padding?

6. Why it matters for robotics

  • Same block, different tokens. Many robot foundation models (vision-language-action models) use a GPT-style Transformer backbone and predict actions as tokens. nanoGPT's Block is that backbone in its plainest form.
  • Causal masking matches time. A robot controller can only use the past. The causal mask that stops a GPT peeking at the next character is the same rule for a policy that reads a history of observations.
  • Small models on small machines. The Shakespeare runs show what a laptop-class chip can train in seconds or minutes. Onboard robot computers are in the same class, so knowing how loss, size and speed trade off is practical.
  • What it doesn't do: nanoGPT has no images, no actions and no robot data. Turning it into a robot policy means new tokenisers and new data, which is the hard part.

7. Reality check

  • Deprecated. The README itself sends you to nanochat. Expect no fixes. We saw deprecation warnings (torch.cuda.amp.GradScaler) on PyTorch 2.15.0, though everything still ran.
  • The GPU numbers are for GPUs. "3 minutes, val loss 1.4697" is on an A100. The same config on the M4's MPS ran at a median of 1.21 s per iteration, so the full 5000 iterations would take well over an hour.
  • MPS isn't always faster. For the tiny 0.8M model, CPU and MPS took about the same time per step. The GPU only pays off once the model and batch are big enough to keep it busy.
  • Character-level is a toy. Real models use tokens (GPT-2's BPE has 50,257). The shakespeare (not _char) data folder and the finetuning config show that path.
  • The GPT-2 reproduction needs OpenWebText and about 4 days on 8×A100 40GB. nanochat now gets past GPT-2's CORE score in under 2 hours on 8×H100, thanks to better data, optimisers and precision.
  • Overfitting. The small Shakespeare set is about 1 MB. The config's comment says "we expect to overfit", which is why it only saves when val loss improves.

8. Self-check

What two lines make up a Transformer Block's forward pass, and why the "x +"?

x = x + attn(ln_1(x)) and x = x + mlp(ln_2(x)). The "x +" is the residual connection: each sub-layer adds a correction instead of replacing x, so gradients flow straight through and deep stacks still train.

What does "causal" mean in causal self-attention, and how is it enforced?

A position may only attend to itself and earlier positions. The scores for future positions are set to −∞ before the softmax (or is_causal=True in PyTorch's fused version), so they get weight 0.

Our Lesson 15 attention can't tell word order. What in nanoGPT fixes that?

The position embedding table wpe: a learned vector for each position, added to each token's embedding before the first block.

Why did MPS not beat the CPU on the 0.8M-parameter run?

The model and batch (12 × 64 characters) are tiny, so there isn't enough work to keep the GPU busy, and moving data and launching kernels costs time. On the bigger config, the GPU matters much more.

What does nanochat cover that nanoGPT doesn't?

Everything after pretraining and around it: training its own tokenizer, finetuning (SFT), reinforcement learning, evaluations and a chat interface with a KV-cached inference engine. nanoGPT only pretrains (and can finetune on text).
